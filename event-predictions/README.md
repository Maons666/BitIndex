# 事件分析、影响分级与预测留档

此目录与旧 `predictions/forecasts` 的 14 份 Ridge 留档分开。它保存用户触发 agent 分析后实际签发的结果；刷新网页及每日任务不生成新的事件预测。

## 数据结构

- `cases.json`：人工核实的历史案例，含候选主导事件、共同因素、来源与公开时间。
- `historical-prices.json`：用于案例分级的真实价格窗口；保存原获取时间。
- `library.json`：每个案例的 7/30 日表现与影响等级，含计算输入指纹。
- `research.json`：用户指定四段行情的事后复盘。不可作为实时预测成绩。
- `analyses/<id>.json`：当次 agent 判断、来源、截止时间、相似度和情景条件。
- `inputs/<id>.json`：当时 61 个日收盘价和完整历史案例库快照。
- `forecasts/<id>.json`：签发时间、冻结的 7/30 日目标、三种情景、分级匹配及所有计算参数。
- `forecast-lock.json`：已发出预测的 SHA-256；读取时同时按保存的分析/行情复算核对。
- `replays/<id>.input.json`：事后回放的固定研究包、真实获取时间、价格和案例定义。
- `replays/<id>.report.json`：当前模型逐日起点回放的结果，明确标记 `retrospective-current-model`；不属于真实签发预测，读取时逐点复算校验。

## 每日 30 天预测差距

预测页的“每天预测差了多少”提供历史回放和真实留档两个视图。每个目标日对应其前 30 天的预测起点；历史回放截止为 16:00 UTC，日线保守滞后 2 天。模型方程保持不变。Agent 先固定历史证据及评分，按公开/可用时间截断，重复新闻流只取最新可用状态；案例等级从每个起点可见的历史行情重新计算。

回放由 `node dashboard/build-replay.mjs <固定输入.json>` 手动创建。同名记录不能覆盖，修正需新 ID。首批目标日为 2026-10-14 至 2026-11-12，起点为 2026-09-14 至 2026-10-13，研究重建于 2026-11-14 UTC（纽约 11 月 13 日）。每日后台任务只追加真实实际价和已有真实预测的对照，不自动延长历史研究包，不重新生成 agent 判断。

回放属于当前历史数据版本的事后检验：原始历史发布版本不完整、案例库和模型事后选定、agent 今天重建判断，存在选择偏差与事后认识影响。30 天窗口重叠，不能当作独立试验；成绩与真实到期成绩分开。MAPE、美元平均绝对误差及两个基线均用同一批精确目标日计算；范围是情景包络，不是置信区间。

真实日线与逐日对照位于数据分支 `tracking-data`：`predictions/actuals/` 固定首次记录值，`predictions/events/comparisons/` 固定每日对照。只在精确目标日计算误差；后续修订另由原系统的 observations 记录。7 天和 30 天分别比较事件模型、相同价格模型不加事件、价格不变基准。观察期重叠，不能把所有逐日记录当作独立样本。

## 影响等级

历史案例以公开日前一日收盘为起点，只用此前 60 日日收益估计趋势与波动。观察事件窗口结束价相对纯价格趋势的对数偏离，再除以事前日波动率乘 √h，得到 z：

| 等级 | 标准化偏离绝对值 | 含义 |
| --- | --- | --- |
| L1 | < 0.5 | 轻微 |
| L2 | 0.5 至 < 1 | 中等 |
| L3 | 1 至 < 2 | 显著 |
| L4 | ≥ 2 | 极端 |

7 日与 30 日独立评级。等级描述整个窗口的异常表现，不是已识别的事件因果效应。历史“主导事件”是候选归因；共同新闻、既有趋势、资金流和杠杆都有可能影响结果。初始四例由用户指定，存在选择偏差，尚不能训练出可靠的事件价格系数。

新事件根据经济渠道匹配此前已公开且观察期结束的同类案例，展示中位等级和样本数。Agent 另判断新事件方向、相似程度、影响把握及尚未消化的比例，并解释理由。按 n/(n+5) 收缩小样本结果、7 日半衰期降低旧消息权重，同一渠道取平均避免新闻重复计数。没有案例标“待积累”，不编造等级；不代表其没有风险。

新预测使用近 7/28 日收益趋势（收缩系数 0.35）、近 28/60 日波动率较大值，加上有上限的事件情景修正。精确公式见预测页统一说明及 `dashboard/event-model.mjs`。偏弱/偏强为 ±1 倍时间尺度波动的情景包络，没有校准的概率含义，不声称模型优于基准。

## 下一次免费更新

1. 用户在对话中说“更新事件研判并发布”。Agent 读取最新真实快照与波动候选清单，核查过去 28 天的相关公开信息；保存事件日期、公开日期、核查时间与来源。动态页面无发布时间时采用首次核查时间，不能猜测历史可用时间。
2. 对新完成的案例补充候选归因、共同因素及证据。先更新 `cases.json`，再运行 `node dashboard/build-event-library.mjs <真实行情快照.json>`。不要仅挑选支持既有观点的行情；待归因清单保留反例与未知案例。
3. 写新的 analysis JSON，参照现有 `analyses/` 字段。新 ID；截止时间必须真实、距签发不超过 24 小时；禁止借用未来消息或补造过去预测。
4. 运行 `node dashboard/publish-analysis.mjs <新分析.json> <真实行情快照.json>`。行情至少有最近 61 个连续完整日收盘，末日不能超过 3 天。程序冻结输入、案例库和目标；拒绝覆盖同名记录。
5. `npm test`；使用最新 tracking-data 缓存构建和验收；推送代码与新留档，GitHub Pages 发布。

每天 09:23（America/New_York）的既有 Actions 只更新真实价格和对照；代码发布不重复抓取行情。预测页显示行情、事件截止与签发三个不同时间。无模型 API Key、无后台自动 LLM 调用，未新增付费服务。

当前案例仅覆盖四段已核查行情。2026 年显著单日波动扫描自动产生待研究线索，但不会自动从价格猜测原因。后续应持续记录反例、无反应事件和相似事件的差异，积累足够独立样本后再校准等级与价格影响关系。
